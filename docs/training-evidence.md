# 비개발자용 설명

근력 분석은 운동일지에 실제로 적힌 세트와 중량을 읽고, 비교할 수 있는 조건과 확인이 필요한 조건을 나눈다. 같은 실제 장비에서 `40kg × 10회 → 45kg × 10회`로 기록이 바뀌고 외부 중량 역할·중량 기준·세트 수·RIR·확인한 순차 수행 맥락이 같다면 기록상 증가로 표시한다. 이를 실제 근육 증가량이나 진단으로 바꾸지 않는다.

예전 사진처럼 RIR과 한쪽·합산 중량 기준이 비어 있어도 숫자를 숨기지 않는다. `50kg × 10회 → 50kg × 12회`는 관찰된 기록 변화로 보여 주되, 같은 노력 수준에서 수행이 향상됐다고 확정하지 않는다. 다른 머신의 표시 중량을 서로 환산하지 않고, 몸무게나 빈 값을 0kg으로 채우지도 않는다.

최근 28일의 직접·간접 세트는 따로 표시한다. 벤치 프레스 일반 세트 3개는 이 제품 분류에서 가슴 직접 3개, 어깨·삼두 각각 간접 3개다. 이를 합쳐 총 9개짜리 자극이나 건강 점수를 만들지 않는다. RIR을 모르는 세트도 기록된 세트 수에는 남지만, 유효 세트나 충분한 자극이라고 이름 붙이지 않는다. W는 준비 세트로 제외하며 D·A·그 밖의 표시는 원문을 유지하고 별도 표시 세트로 집계한다. 드롭세트나 보조 세트라고 자동 해석하지 않는다.

프로그램은 일반 성인을 위한 시작 예시다. 주 1~6회, 회당 20~150분, 헬스장·덤벨이 있는 집·추가 장비 없는 맨몸 조건을 반영한다. 운동 경력이 없으면 주간 횟수로 고급자 여부를 추측하지 않는다. 맨몸만으로는 등·이두의 점진적 부하에 한계가 있으며, 시간이 짧거나 장비가 없어 요청한 부위의 직접 동작을 넣지 못하면 한계에 명시한다. 모든 사람에게 완벽한 개인 PT나 대회·재활 처방이라는 주장은 하지 않는다.

통증 때문에 중단해야 한다고 기록하면 수행 기록이 좋아도 중단 안내가 먼저다. 반복적인 수행 저하와 최근 회복 관련 자기보고가 함께 있어야 디로드를 **검토할 이유**로 표시한다. 하루의 낮은 기록만으로 과훈련이나 디로드 필요를 단정하지 않는다. 성별·체중·체지방률에서 특정 기구의 적정 중량을 만들어 내지 않는다.

정책·계산 변경: 별도 근력 분석과 시작 프로그램에 저장·일정·실제 수행 비교·다음 계획 조정을 연결했다. 근력 모듈이 영양 목표·등열량 배분·완료일 스냅샷을 변경하지는 않는다. 순수 분석 함수는 사용자 기록이나 프로필을 수정하지 않고, 화면의 명시적 저장은 별도 검증 경계를 통과한다.

## 실제 해석 규칙

- 기간은 선택 날짜를 포함한 28일이다. 미래 기록과 잘못된 날짜는 제외한다. 날짜가 비면 모든 빈 날짜를 휴식일로 채우지 않는다.
- 같은 날짜의 오전·오후 세션은 따로 남긴다. 같은 날 세션끼리는 피로·순서의 영향을 분리할 수 없어 장기 수행 변화 판정을 하지 않는다.
- 같은 기록 ID의 완전 복사본은 하나만 사용하고, 동일 ID에 상충하는 내용은 집계에서 제외한다. 같은 이미지 해시·날짜·시간·세트 내용의 사본도 중복 집계하지 않는다.
- 같은 운동을 한 세션 안에서 여러 블록으로 기록하면 각각 보존하고 선행 맥락도 따로 계산한다. A→B→A의 앞뒤 A를 합치지 않는다. 표시 순서는 실제 순서가 확인된 경우에만 수행 순서로 사용하며 슈퍼세트·교차 수행의 선행 세트 수를 순차 수행처럼 계산하지 않는다.
- 대표 세트는 확인된 일반 세트 중 표시 중량이 가장 큰 세트이고, 같으면 반복 수가 많은 세트다. 이 선택은 제품의 설명 가능한 표시 규칙이며 추정 1RM 계산이 아니다. 일반 세트가 없으면 표시가 붙은 세트도 관찰값으로는 남기되 비교 판정을 하지 않는다.
- 비교 판정에는 서로 다른 날짜, 동일 장비 키, 확인된 외부 중량 역할과 한쪽 또는 합산 규약, 동일한 기록 RIR·일반 세트 수·확인된 순차 수행 맥락이 필요하다. 같은 날짜의 다른 세션 선후도 추측하지 않는다. 한 변수만 바뀌면 중량 또는 반복 수의 기록 변화로 표시한다. 중량과 반복 수가 동시에 바뀌면 mixed로 남긴다. 보조 중량과 순서 미확인은 관찰로 남으며 반복 저하·디로드 근거로 승격하지 않는다.
- 몸무게 운동의 외부 중량 0과 실제 체중 부하를 같게 취급하지 않는다. 현재 체중을 과거 운동에 끼워 넣어 비교하지 않는다.
- 사용자에게 확인된 운동 ID가 있으면 기록의 운동 선택을 우선한다. 별명 매핑은 확인된 것만 적용하며 장비 키·규약으로 범위를 좁힌다. 확인되지 않은 이름에 유사 문자열만으로 임의 대응하지 않는다.
- 일반 종목명 카탈로그는 머신 플라이(펙 덱)·머신 숄더 프레스·머신 암 컬·덤벨 불가리안 스플릿 스쿼트·덤벨 스티프 레그 데드리프트·케이블 암 풀 다운·스미스 시티드 숄더 프레스·뉴트럴 그립 랫 풀 다운·스미스 언더그립 벤트 오버 로우·케이블 로프 푸시 다운을 포함한다. 이름에 명시된 그립·동작·장비 변형은 기존 일반 종목과 별도 ID로 보존한다. 이번 추가는 인식 누락 보완이며 기존 프로그램 종목과 세트 처방은 바꾸지 않는다.
- 정확한 일반 동작명과 브랜드·모델 확인은 별개다. `머신 플라이`를 가슴 동작으로 분류해도 장비 키가 없는 두 머신의 부하를 비교하지 않는다. 카탈로그에 없는 Drax·Infinity·STA7000 모델명을 접두어 제거로 추측하지 않고, 실제 동작과 장비를 확인한 사용자 매핑이 필요하다. 모든 운동명을 지원한다고 주장하지 않는다.
- `W웜업풀업` 같은 이름은 풀업 동작을 식별할 수 있지만, 이름에서 세트별 준비 여부·RIR·체중 부하를 만들어 내지 않는다. 준비 세트 제외는 각 세트에 명시된 W에만 적용한다. 표기 없는 세트는 일반 기록 수에 남을 뿐 충분한 자극 또는 성장 유효 세트라는 뜻이 아니다.
- 불확실한 과거 OCR의 총 세트·총 볼륨은 부위별 숫자로 쪼개지 않는다. 기록된 Cal은 이 모듈에서 실제 소모량으로 재사용하지 않는다.
- 통증은 마지막으로 명시한 상태를 읽는다. 미입력을 통증 해소로 취급하지 않으며 현재 상태가 달라졌으면 명시적으로 갱신할 필요가 있다. 여기서 통증의 원인이나 치료법을 판단하지 않는다.

카탈로그의 동작 분류에는 [ACE의 펙 덱 원 연구 보고](https://www.acefitness.org/certifiednews/images/article/pdfs/ACE_BestChestExercises.pdf), [ACE 스트레이트 암 프레스다운 설명](https://www.acefitness.org/resources/everyone/exercise-library/334/straight-arm-pressdown/), [스티프 레그와 루마니안 데드리프트 비교 실험](https://pubmed.ncbi.nlm.nih.gov/35162922/)을 참고했다. 팔꿈치 굽힘을 사용하는 랫 풀 다운과 팔을 편 어깨 폄 동작을 구별하고, 스티프 레그와 루마니안 변형도 같은 수행 비교로 묶지 않는다. 문헌의 동작 설명·근전도 관찰은 분류의 근거일 뿐이다. 직접·간접 세트의 이진 구분은 제품의 대표 해부학적 분류이며 특정 사용자의 근활성·유효 자극량·근성장률 측정이나 장비 환산 계수가 아니다.

## 저장 계획과 실제 수행

### 세션 맥락과 개인 중량 참고

[운동 순서 메타분석](https://pubmed.ncbi.nlm.nih.gov/32077380/)은 먼저 수행하는 종목의 근력 적응이 더 클 수 있음을 보여 준다. 이 결과에서 개인의 순서별 피로율이나 머신 치환 계수를 얻을 수는 없다. [프리웨이트·머신 메타분석](https://pubmed.ncbi.nlm.nih.gov/37582807/)에서도 검사·훈련 방식의 특이성이 나타나므로 운동 계열의 연결과 중량의 동등성을 구분한다.

제품의 중량 참고는 최근 해당 실제 장비의 **첫 일반 세트**를 먼저 사용한다. 최고 중량 세트와 구별하며 같은 조건의 기록이 없으면 조건이 다른 실제 관찰임을 표시한다. 장비마다 이력을 유지하므로 5:5나 여러 머신 순환에 주 장비를 강요하지 않는다. 선행 세트는 관련 부위가 겹치는 일반 기록을 한 번씩 세는 대표 분류이며 준비·특별 표기·미확인 부위를 따로 둔다. 세션 순서와 순차 수행이 미확인이면 선행 세트 수는 null이다.

개인 치환은 같은 운동 또는 명시적 제한 계열(현재 수평 벤치/덤벨 벤치/머신 체스트 프레스)만 허용한다. 인클라인·플로어 프레스·푸시업을 넓은 밀기 패턴 하나로 환산하지 않는다. 최근 대상 장비 기록이 없고, 확인한 실제 장비·외부 중량 역할·중량 규약·순차 맥락·같은 반복/RIR의 서로 다른 날짜 관찰 짝이 충분할 때만 표시 중량의 개인 관계를 참고한다. 보조/맨몸 부하, 현재 통증·회복 경고, 미확인 예정 맥락은 치환에서 제외한다. 관찰 범위를 벗어난 외삽·연쇄 환산·덤벨 두 배 공식은 없다. 원문 kg는 수정하지 않는다.

직접 기록 우선 기간 28일, 관찰 범위 90일, 새 원본 14일, 관찰 짝의 간격 7일 이하·최소 3개는 **제품의 자료 선별 정책**이다. 최소 짝 수를 채워도 개인의 저항 동등성이 검증되는 것은 아니다. 표시 범위는 관찰 중량 관계의 제한 범위이지 신뢰구간·성공 확률·처방 범위가 아니다. 자료가 부족하면 같은 운동 계열의 맥락과 첫 실제 세션 확인을 이어가되 kg를 발명하지 않는다. 원본 수정·순서 교정은 새 계산에만 반영되며 과거 상담과 완료 목표는 보존한다.

시작 초안은 저장한 프로그램, 실제 날짜에 배치한 계획, 실제 운동일지의 세 단계로 구분한다. 사용자는 프로그램의 운동·세트·반복 범위·RIR·휴식과 선택적 중량·장비 기준을 편집할 수 있다. 날짜에 배치할 때 그 계획을 복사해 두므로 원본 프로그램을 나중에 수정해도 이미 배치한 목표가 몰래 바뀌지 않는다. 빈 날짜나 아직 연결하지 않은 계획은 휴식·실패·수행으로 처리하지 않는다.

- 선호·제외 운동은 저장해 이후 초안을 만들 때 반영한다. 선호는 가능한 장비 안에서 같은 움직임 분류의 후보를 고르고, 제외 후 빠진 움직임이 모두 대체됐다고 보장하지 않는다. 새 운동으로 바꾸면 이전 운동의 개인 중량·장비 기준을 자동 승계하지 않는다. 카탈로그에 없는 가져온 ID·원문 이름은 다른 운동으로 조용히 교체하지 않고 보존한다.
- 계획 이행은 사용자가 연결한 같은 날짜의 실제 일지와 비교한다. 같은 운동 ID의 표기 없는 일반 세트 중 계획한 수만큼의 반복 범위와 최소 RIR 여유를 비교하고, 미입력은 모름으로 둔다. W와 다른 문자 표시 세트는 이 비교에서 제외한다. 계획 중량이 있으면 같은 장비·확인된 중량 규약도 필요하다. 추가 세트는 실제 기록에 남지만 계획한 세트의 평가와 구별한다.
- 같은 종목을 다른 장비 또는 여러 블록으로 계획할 수 있다. 블록 ID는 유일하며 실제 세트 하나는 계획 블록 하나의 평가에만 사용한다. 반복 블록의 대응 순서·장비가 애매하면 달성으로 확정하지 않는다. 프로그램 장비/중량 규약을 바꿨는데 기존 중량 숫자가 그대로이면 자동 승계하지 않고 비운다. 이미 날짜에 배치한 처방은 보존한다.
- `계획 범위 충족`은 기록된 수치 조건의 일치다. 휴식시간·자세·동작 범위·적절한 피로·성장 자극을 확인한 결과가 아니다. 반복 상단 충족도 자동 증량 버튼의 처방 근거가 되지 않으며, 다음 중량은 사용자가 같은 장비와 기준을 확인하고 선택한다.
- 유지·증량 검토·디로드는 수행하지 않은 날짜별 계획에 명시적으로 적용한다. 이유와 재검토 날짜를 저장하고, 조정 전 원래 목표를 보존한다. 디로드의 세트 감소와 RIR 여유 증가는 사용자가 선택하며 정해진 비율·주기로 자동 적용하지 않는다. 완료한 영양 날짜, 이미 수행한 계획, 임상·통증 맥락은 수치 조정에서 보호한다. 회복 경고가 있으면 증량 적용을 막고 확인을 요청한다.
- 재검토 완료 표시는 사용자가 검토했음을 뜻한다. 통증 해소·회복 완료·처방의 효과를 자동 인증하지 않는다. 조정 정보는 현재 선택과 최초 계획을 남기는 구조이며 모든 중간 편집의 완전한 버전 이력은 아니다.

개인 코치의 제약·우선순위·합의는 사용자 확인 후 별도 기억에 저장한다. 후속 약속은 주제·메모·검토 날짜·열림/완료 상태를 보존하며, AI 제안만으로 훈련 계획이나 실제 기록에 적용하지 않는다. 최근 기록과 질문에 관련된 일부 과거 맥락을 대화에 연결하지만, 누락 없는 평생 기억이나 관찰하지 않은 운동 기술 평가를 보장하지 않는다. AI의 수치 출처 확인과 자유 문장 검증의 차이는 [영양·코칭 근거 문서](evidence.md)에 정리했다.

## 기술 검증

`src/training.js`는 DOM·저장소·시간 전역에 의존하지 않는 UMD 모듈이다. `MacroTraining`과 Node의 `module.exports`로 같은 API를 제공한다. 기준 날짜가 없고 기록도 없으면 날짜를 만들지 않는다. 기록만 제공된 경우 최신 기록 날짜를 분석 끝으로 사용한다.

공개 API는 `catalog`, `muscleLabels`, `resolveExercise(rawName, mappings)`, `analyze(records, options)`, `recommendProgram(profile, settings, analysis, preferences)`, `createProgram(draft, options)`, `createAssignment(program, dayId, date, id)`, `evaluateAssignment(assignment, records)`, `adjustAssignment(assignment, change, context)`다. `src/training-store.js`는 실제 일지와 계획·날짜 배치·선호·기억·후속 약속을 별도로 검증하며 중앙 백업에 포함한다. 실사용자의 일지나 이미지를 테스트 fixture에 넣지 않았다. 테스트는 합성 자료로 작성했다.

검증 범위: 기간 경계·미래·오류 날짜, 미입력과 숫자 0 구분, 원문 표시, 준비 세트 제외, 직접·간접 집계, 같은 날 두 세션, 중복·충돌 ID, 장비·규약·RIR 불일치, 관찰값 보존, 반복 저하와 자기보고 조합, 통증 우선, 임상·연령 지원 범위, 프로그램 조합, 시간 증가 시 세트 수 비감소, 기록 세트 추가 시 집계의 정확한 증가, 입력 불변성. 저장 계획은 배치 당시 목표 보존, 미기록 상태, 실제 일지 연결, 미확인 값과 계획 비교, 명시적 조정·재검토, 미등록 운동 보존, 백업 왕복과 좁은 화면 흐름도 검증한다. 테스트 통과는 임상적 검증이나 개인별 정확도 보증이 아니다.

판단 기록: README·영양 근거 문서·제품 검토 스킬과 실제 추출/기록 경계를 확인하고 `npm run preflight:product`를 통과했다. 단순 kg×반복 그래프나 생성형 문장만으로 코치를 구현하는 대신, 실제 기록·부위 분류·비교 판정·프로그램 예시를 분리하는 순수 엔진을 선택했다. 반증 조건은 미확인 장비를 합쳐 성장으로 표현하거나, 미입력을 0으로 만들거나, 같은 날 두 세션으로 반복 저하를 확정하거나, 통증 상태에서 자동 증량을 권하거나, 프로그램 생성이 사용자 기록·영양 목표를 바꾸는 경우다.

보류: 동작 영상·관절 통증 평가, 머신 저항 교정, 경기 일정에 따른 종목별 주기화, 실제 근비대 측정, 부상 재활 및 질환별 처방. 구현된 일정·기록·조정 흐름을 이 보류 영역의 완성으로 표현하지 않으며, 실제 사용 피드백과 독립적인 개인별 타당성 평가는 여전히 필요하다.
