# 비개발자용 설명

날짜별 기록은 각 단계가 끝났을 때의 상태를 보존한다. 이전 단계의 보류 항목과 테스트 결과는 현행 기능 목록이나 최신 검증 결과가 아니며, 이후 구현은 아래의 최신 날짜 기록과 README를 따른다.

## 무엇을 바꿨는지와 이유

2026-10-05 사용자가 기존 제약·스킬·브랜치·폴더까지 다시 판단하도록 위임했다. 한 파일의 여러 시대 계산을 계속 덧대는 방법 대신 실행 앱을 계산, 저장, 추세, 화면으로 분리했다. 기존 약 11만 줄 HTML에 섞여 있던 실험과 테스트는 현재 제품에서 제거하고 Git 이력에 보존했다.

앱은 내 기준을 입력한 뒤 오늘 식사와 운동을 기록하고, 완료한 기록과 몸 상태의 추세를 보는 흐름이다. 운동 횟수로 경력을 추정하지 않고 실제 연수를 받는다. 근력운동·달리기·사이클·수영·팀 스포츠·복합 운동, 날짜별 걷기를 지원한다. 여러 운동은 실제 세션별로 합산한다.

## 실제 계산과 화면의 차이

- 체성분 없는 100kg 사용자의 전체 체중을 제지방량처럼 써서 감량 목표를 3,000kcal로 끌어올리던 경로를 제거했다. 제지방량을 모르면 알 수 없음으로 유지한다.
- 80kg일 때 체지방률 20%를 측정했다면 당시 제지방 참고량은 64kg이다. 이후 체중이 70kg이 되었다고 과거 측정값을 56kg으로 바꾸지 않는다. 날짜와 체중 차이가 커질수록 반영을 부드럽게 줄인다.
- 70kg 사용자의 60분·7 MET 운동은 추가 소모를 `(7-1)×70=420kcal`로 추정한다. 이미 일상 소모에 포함된 휴식분을 또 더하지 않는다. 실제 개인의 측정 소모량은 아니다.
- 탄수화물 25g과 지방 약 11.1g은 각각 100kcal다. 배분을 바꿔도 총열량과 단백질 목표는 유지한다.
- 식사 기록 중에는 하루 부족 판정을 하지 않는다. 완료해야 하루 섭취를 돌아본다. 완료한 목표는 프로필을 바꿔도 보존하고, 명시적으로 다시 열면 새 기준으로 계산한다.
- 회복 관련 주의는 조언 개수 제한 때문에 사라지지 않는다. 적게 먹은 날에 감량을 더 밀어붙이는 조언을 함께 출력하지 않는다.

## 범위와 남은 한계

생리학적으로 완벽하거나 모든 인구에 최적이라는 주장은 하지 않는다. 임신·수유·미성년·질환·섭식 문제 등의 자동 처방은 제공하지 않는다. 자동 목표를 중단해도 식사 기록은 완료할 수 있다. 전문 선수의 측정 RMR, 장애·호르몬 치료·질환별 모델, 식품 검색 데이터베이스, 식단 처방, 식품의 질·미량영양소 평가는 구현하지 않았다.

체성분은 감량 보정·단백질 기준·회복 참고에 사용하고, 안정시대사량을 직접 바꾸는 검증되지 않은 혼합식은 넣지 않았다. 예측식의 개인 오차는 실제 기록과 전문 평가로 확인해야 한다. 체중 추세가 생겨도 자동으로 섭취량을 계속 깎지 않는다. 이 버전은 로컬 사용과 검토가 가능한 릴리즈 후보이며 임상 검증이나 공개 배포 완료를 의미하지 않는다.

# 기술 검증

## 2026-10-05 코치 의도 재확인

사용자가 원한 것은 계산기 부속 조언이 아니라 운동·식사·회복을 함께 기억하고 판단하는 개인 코치였다. 기존 코치의 상태→이유→행동 구조와 생활·운동 계획·섭취 여건은 보존할 가치가 있었다. 점수 연결을 제거하는 것과 코치의 맥락을 삭제하는 것은 별개의 판단이며, 첫 리빌드에서 그 역할을 축소한 점을 수정했다.

진행하던 UI·영양 코치 수정은 중간 구현으로 남긴다. 짧은 초기 설정, 작성 중 프로필 유지, 오늘 코치의 전면 배치와 별도 코치 화면, 실제 식사 직후 피드백, 선택적 컨디션·계획·식사 여건 입력을 연결했다. 체크인은 입력하지 않은 값을 모름으로 보존하고 예정 운동은 실제 소모로 가산하지 않는다. 정책·영양 산식 변경 없음. 저장 데이터에는 선택적 coachCheckin만 추가했으며 기존 v9 기록과 완료 당시 목표는 유지한다.

수용·통합: 코치 중심 흐름, 확인된 기록과 자기보고의 구분, 같은 목표로 완료한 최근 기록, 실제 운동과 예정 운동의 분리. 폐기: 일반 문구 목록만으로 개인 PT가 완성됐다는 판단. 보류: 운동 일지 이미지 추출, 운동명·머신별 별칭, 세트·반복·RIR 기록, 부위별 볼륨, 프로그램과 디로드 제안, AI 자유대화·장기 기억 연동. 금지선: 운동량을 근성장률로 둔갑시키기, 불확실한 이미지 내용을 영구 기록으로 확정하기, 단 하루 저하로 디로드를 처방하기.

후속 방향은 앱=개인 기억·확인·계산·변경 이력, AI=비정형 입력 해석·질문·대화로 분리하는 가설이다. Codex 연동으로 입력 부담과 실제 코칭 가치를 먼저 검증하고 독립 앱 AI 연결 여부를 판단한다. 다음 구현을 자동으로 시작하거나 현재 로컬 코치를 전체 요구의 완성으로 보고하지 않는다.

중간 구현 검증: preflight 통과, 단위 테스트 66개 통과, 첫 설정·미저장 초안 유지·체크인 6항목 왕복·완료일 명시적 재개·파일 직접 열기·320/390/1280px의 실제 브라우저 흐름 통과, 저장·복원 브라우저 시나리오 8개 통과. 체크인 조합 3,840개에서 영양 목표가 바뀌지 않음을 확인했다. 화면 캡처를 직접 검토했으며 콘솔 오류와 페이지 가로 넘침은 없었다. 이는 개인 AI 코치나 임상 판단을 검증한 것이 아니다. 기존 공개 원격과 master에는 아직 이 중간 변경을 반영하지 않았다.

### 기술 검증

`tools/diary.cjs`는 SHA-256 이미지 인덱스, 초기 과거 OCR 보관, 날짜 범위 context, immutable 원문 추출, append-only 교정 revision과 CAS를 제공한다. 수정된 이미지의 이전 세션은 새 이미지의 알려진 날짜·시간·제목이 일치하는 경우만 별도로 보관하고, 단순 파일명 재사용·이름 교환·원본 복원은 기록 소실로 처리하지 않는다. 손상은 해당 source만 격리하며 config·manifest·교정 head 누락은 조용한 재초기화 대신 복구 상태로 알린다. 원본 연결 여부는 마지막 성공 스캔 시각 기준이다.

`tools/organize-diary.ps1`은 전체 이동 계획의 경로·날짜·분류·충돌을 먼저 검사하고, dry-run과 이동 journal 및 전후 해시 확인을 제공한다. `coach-diary` 스킬은 실제 CLI를 이용한 독립 합성 시나리오로 신규/캐시 분리·교정 충돌·손상 상태를 forward-test했다. 스킬 형식 검증도 통과했다. 검증용 PyYAML은 앱 의존성이 아닌 Git 제외 테스트 산출물 경로에만 설치했다.

추가 일지 테스트 19개와 Windows 이동 테스트 3개, 기존 계산·저장·코치 검증을 합친 단위 테스트 88개 통과. 실제 브라우저 흐름은 320/390/1280px 및 파일 직접 열기에서 통과했고 저장·복원 브라우저 8시나리오도 통과했다. Windows 이동 테스트는 비Windows CI에서는 해당 플랫폼 테스트로 건너뛴다. 테스트는 데이터 흐름과 회귀를 검증하며 개인별 생리학 정확도를 증명하지 않는다. 실제 사용자 이미지·추출·개인 경로는 커밋하지 않는다.

## 2026-10-06 개인 코칭과 운동 일지 연결

사용자가 원한 PT 경험은 일반 조언 목록이 아니라, 이전 운동을 기억하고 오늘 상태를 확인한 뒤 실제로 할 일을 함께 정하는 흐름이었다. 영양 코치를 전체 요구의 완성으로 취급하지 않고, 앱의 확인 가능한 기록과 계산을 중심에 두면서 비정형 이미지 해석·질문은 별도 AI 연결로 확장했다. 이 단계에서는 앞서 보류했던 세트 일지·별칭 확인·분석·프로그램·대화를 화면과 저장에 연결했다.

- 운동 일지에서 직접 입력·수정·복사, 이미지·JSON 초안 확인, 원문·출처·미확인 값 보존을 지원한다. 같은 날 두 세션은 별도로 남기고, 충돌한 가져오기는 비교·선택 전 기존 기록을 대체하지 않는다. 완료한 영양 목표는 일지 수정이나 대화로 바뀌지 않는다.
- 운동명을 확인하면 최근 28일의 직접·간접 기록 세트와 관찰된 중량·반복 변화를 보여 준다. 같은 부위 분류와 같은 장비에서 비교 가능한 수행은 별개다. 미등록 브랜드·모델은 추측하지 않고 확인을 요청하며, 일반 동작·그립 변형을 보완해도 부하를 환산하지 않는다.
- 통증, 회복 자기보고, 반복 수행 저하를 구분하고 디로드는 검토 대상으로만 안내한다. 개인 프로그램은 경력·목표·시간·장비·우선 부위에 맞춘 시작 예시다. 예정 세트는 실제 수행으로 채우지 않으며, 적정 중량·근성장률·단일 저하의 원인을 만들어 내지 않는다.
- 앱코치 대화는 로컬 기록 해석과 선택한 Codex 응답의 출처를 표시한다. 작성 중 질문, 이어 묻는 원문, AI가 표시한 판단 한계를 보존한다. 감지한 통증·긴급 증상은 AI 대기를 거치지 않고 먼저 안전 안내로 연결한다. 답변과 이미지 초안은 진단·연구 근거 또는 자동 변경 명령이 아니다.
- 운동일지의 시간은 사용자가 실제 종목·강도·중복 여부를 확인한 뒤 영양 기록에 연결한다. 원문의 Cal·kg를 소모 열량으로 재사용하지 않는다. 이미지 체성분의 미판독 항목은 같은 날짜의 기존 측정을 조용히 지우지 않으며, 기존값 유지와 새 측정으로 교체를 확인받는다.

수용·통합: 실제 기록을 기억하는 코치, 관찰과 해석의 분리, 입력 부담을 줄이는 확인 가능한 초안, 다음 운동으로 이어지는 행동. 폐기: kg×반복을 성장률로 표현하기, 같은 운동명이면 머신 부하도 같다는 가정, AI 문장을 권위 있는 처방으로 취급하기. 보류: 영상 기반 동작 평가, 재활·질환별 처방, 머신 저항 교정, 경기별 주기화, 실제 근비대 측정과 보편적 개인 최적화.

정책 변경은 근력 기록의 분류·비교·회복 검토·시작 템플릿과 선택적 AI 입력 경계다. 기존 영양 산식·등열량 배분은 이 작업에서 변경하지 않았다. 논문·공식 권고가 뒷받침하는 범위와 제품 휴리스틱은 [근력 근거 문서](training-evidence.md), 영양과 생성 AI의 적용 한계는 [근거 문서](evidence.md)를 따른다. 생성 AI 응답이나 회귀 테스트 통과는 모든 사람·임상군에 대한 생리학적 타당성 검증이 아니다.

검증 대상은 종목·장비·규약·RIR 경계, 기록 불변성, 완료 목표 보호, 합성 일지 입력·복사·매핑·시간 연결, 가져오기 충돌과 백업, 로컬 대화·AI 요청 상태, 이미지 미확인 값과 초안 재개, 저장 실패·재연결, 좁은 화면과 키보드 흐름이다. 실제 사용자 이미지·추출·개인 경로를 테스트 fixture로 커밋하지 않으며, 최종 실행 결과는 릴리즈 확인 시 별도로 보고한다.

최종 로컬 검증: 단위 테스트 225개와 전체 브라우저 검증 통과(320/390/1280px, 파일 직접 열기 포함). 요청 시작 지연의 중복 제출, 긴 대화 위치, 서버 토큰 교체·최초 연결 실패 복구, 변경 없는 재접속의 이전 백업 보존도 회귀로 고정했다. 실제 설치된 Codex의 합성 대화·이미지 판독을 별도로 확인했으며 일반 테스트와 CI는 AI를 호출하지 않는다. UTF-8·제품 preflight·스킬 형식 검사도 통과했다.

- 유지: 순수 영양·훈련 계산, 실제/계획·관찰/추정 구분, 완료 당시 목표, 원본·교정·출처, 기존 재사용·체크인·프로그램·기억·점검·백업. 일지 이미지를 상담마다 다시 판독하지 않는다.
- 입력 개선: 여러 사진 선택/붙여넣기와 확인함을 통합하고 원문 옆에 전체 판독 요약을 보여준다. 미판독·충돌·새 장비를 우선 강조하되 확인되지 않은 나머지 숫자를 자동 확정하지 않는다. 같은 이름·장비 연결과 사용자의 원암/덤벨 한쪽·바벨 전체 규칙을 재사용하며 변형·머신 차이는 보존한다.
- 코치 개선: 질문의 기간·운동·비교 대상을 공유 계산 엔진으로 정확히 조회하고 답변에 사용한 범위·출처·빠진 조건을 짧게 표시한다. 현재 28일 집계와 제한된 원문을 장기 기록 전체처럼 표현하지 않는다. 새 진술과 오래된 기록은 시점·출처를 나눠 확인한다.
- 행동 개선: 처음에는 기존 계획 편집·일정·식사 조정 화면으로 직접 이어 주고 선택한 행동·비교할 기록·점검을 연결한다. 다음으로 앱이 이미 지원하는 계획 선택·일정 이동·배분·부담 조절을 검증 가능한 변경 초안으로 묶어 변경 전후 확인 뒤 반영한다. AI가 임의의 새 숫자 처방을 만들어 적용하는 기능은 별도 후속 범위이며 구조화 초안·앱 검증·취소/복구를 갖추기 전에는 지원한다고 표시하지 않는다.
- 첫 화면: 날짜/완료 상태 → 오늘 이어갈 운동 또는 점검 → 사진·지난 운동·식사 빠른 기록 → 식사/컨디션 요약 → 미확인 항목 순으로 재배치한다. 계획이 없으면 만들지 않고, 상세 수식·세트·추세·설정은 기존 화면에서 계속 접근한다. 앱 열기만으로 AI를 호출하지 않는다.

### 7일 사용 시나리오

이는 운동 빈도나 식단 처방이 아닌 사용 흐름의 검증 순서다. 새로운 피로·통증이나 장애를 실제로 만들지 않으며 없는 상황은 합성 평가로 확인한다.

| 1일 | 기존 기준은 재사용하고 없거나 바뀐 항목만 입력, 일지 사진 추가 | 기존 프로필 재입력 없이 날짜·숫자·장비를 한 흐름에서 확인 |

| 6일 | AI 불가·판독 실패·재연결 상황 확인 | 사진·메모·입력 초안 보존, 수동/재사용 유지, 숫자 일지와 구분 |

### 구현 순서와 완료 판단

1. 입력·확인·첫 화면을 연결한다. 사진 선택부터 확정까지 사용자 조작 시간, AI 대기 시간, 수정 횟수, 포기 지점을 따로 본다. 익숙한 일지를 1분 안팎에 확인한다는 것은 검증할 제품 가설이며 현재 성능 보증이 아니다.
2. 질문별 기록 조회와 코칭 품질을 검증한다. 흐린 원암 중량/RIR 누락, 감량 중 복합 고민과 새 수면 진술, 3개월 특정 부위 비교, 목표/합의 변경, 기록 공백/AI 실패를 대표 평가로 삼는다. 답변 문구를 고정하는 것이 아니라 올바른 기록·필수 확인·금지할 단정·다음 행동을 평가한다.
3. 선택한 행동과 후속 점검을 연결한다. 앱이 지원하는 변경은 대상·현재 기준·변경 전후·이유·점검 시점을 가진 초안으로 보여 주고 검증·사용자 확인 후 적용한다. 승인 시 기준 기록이 달라졌으면 새로 비교하며 취소/복구를 제공한다. 사용자가 무엇을 왜 선택했는지 이해하고 이후 실제로 실행했는지 살펴볼 수 있어야 한다. 미기록을 효과 없음으로 채우지 않으며 계획 변경과 실제 기록·완료 당시 목표를 혼동하지 않는다.

7일은 사용성과 신뢰 문제를 발견하는 파일럿이며 근성장·감량·대사 보정 효과를 입증하는 기간이 아니다. 개인 사용에서 입력 부담·말투·행동 이해·기억·저장 안정성을 평가하고, 생리학적 조언의 타당성과 공개 대상의 다양성은 전문가·다른 사용자 검토로 별도 확인한다. 발견된 데이터 유실·중대한 숫자/안전 오류는 개인용에서도 감수할 편의 문제로 취급하지 않는다.

보류: 전면 엔진 재작성, 가짜 근성장률/회복 종합점수, 미확인 개인 대사량 추정의 자동 처방, 장비 간 저항 환산, 영상 자세·재활·질환별 처방, 모든 종목 프로그램, 회원·결제·소셜·대형 식품 DB. 개인 사용에서 가치가 확인되면 소규모 공유 후 공개 제품의 AI 연결·접근·사용자별 저장·비용·개인정보 설계를 판단한다.

## 2026-10-06 개인 실사용 기획 구현

위 기획의 입력·조회·행동 점검을 기존 엔진 위에 구현했다. 모바일 설치·앨범 권한·새 로그인 연동·상시 감시와 장비 간 중량 환산은 이번 구현에 포함하지 않는다. 영양 산식·실제 개인 일지·원본 사진은 변경하지 않았다.

- 여러 사진 선택·붙여넣기, 사진별 보관 실패 재시도, 명시적으로 선택한 순차 판독 대기와 통합 확인함을 연결했다. 재시작한 대기는 사용자가 계속하기 전 새 AI 요청을 보내지 않는다. 원본 옆에 전체 세트/식사/측정을 보여 주며 날짜·숫자·장비 기준의 확인을 요구한다. 숫자를 수정하면 확인 상태를 해제하고 미확인 RIR·중량은 채우지 않는다.
- 첫 화면은 배치한 운동·실제 기록·도래한 점검, 빠른 기록, 식사·선택적 컨디션과 확인함으로 이어진다. 없는 계획을 만들거나 완료일 입력을 열지 않으며 작은 화면에서도 다음 행동을 먼저 보게 한다.

- 프로그램 선택·일정 이동·등열량 배분·기존 계획 부담 조절은 현재 기준과 변경 전후·이유·점검 날짜가 있는 초안이다. 확인 후 적용하며 관련 기준이 바뀌면 재비교하고 저장 실패에는 초안을 보존한다. 취소/복구는 이후 변경·완료 목표·실제 수행을 덮어쓰지 않는다. 부담 조절의 관찰 기간은 선택 당시 날짜로 고정한다.

## 2026-10-06 세션 맥락 중심 코칭 설계 보완

사용자가 모든 반례를 제시해야 기능이 넓어지는 접근을 수정한다. 장비 치환 기능만 추가하지 않고, 현재 목표·새 진술·실제 세션 전체·상황 변화·비교 조건·가능한 다음 행동·후속 관찰을 공통 판단 맥락으로 만든다. 아래는 설계와 발견된 구현 공백이며 아직 구현 완료를 뜻하지 않는다. 기존 계산 기반과 완료 당시 목표·원문은 유지한다.

- 장비를 5:5 또는 여러 대 순환해도 주 장비를 강요하지 않는다. 운동 목적·부위 맥락은 연결하고, 실제 장소·물리 장비·동작 변형·부하 역할·단위별 수행 기록은 병렬로 유지한다. 같은 브랜드의 다른 헬스장 머신, 한쪽/합산과 kg/lb, 보조 중량/외부 부하를 먼저 구분한다. 같은 부위·동작 분류만으로 중량 대응을 허용하지 않는다.
- 질문에서 종목을 걸러내기 전에 세션 전체를 해석한다. 각 운동 블록과 세트의 출처를 유지하며 A→B→A의 앞뒤 A를 하나의 대표 수행으로 합치지 않는다. 일지 표시 순서와 확인한 실제 순서를 나누고 슈퍼세트·순환·같은 날 여러 세션의 순서를 모르면 추측하지 않는다. 선행 관련 부위의 기록 세트는 조건 설명이며 피로량·유효 자극량을 측정한 값이 아니다.
- 장비 내 관찰과 개인 시작 중량 추정 모두 선행 운동·일반/특별 세트·변형·노력 수준·기록 시점의 차이를 확인한다. 조건이 다르면 숫자 차이는 보여 주되 근력 저하·디로드 근거로 바로 승격하지 않는다. RIR·휴식의 미입력은 유지하며 과거 최고 중량을 일반 작업 중량으로 사용하지 않는다. 처음 쓰는 조건에는 기록 참고와 첫 수행 확인을 연결하고, 자료 부족을 상담 전체 중단으로 만들지 않는다.
- 사용자의 목표에 따라 같은 기록에서도 다음 행동은 달라져야 한다. 특정 운동 수행을 우선할지, 여러 장비의 구성을 유지할지, 회복·시간 제약에 맞춰 조절할지 구분한다. 목표 변경·복귀·여행·부분 수행·통증과 숫자 상승의 충돌·불완전 식사 기록을 함께 평가한다. 미기록을 휴식이나 결핍으로 채우거나 밀린 훈련을 자동 보충하지 않는다. 실제 결정이 달라지는 확인만 우선하고 추가 상세 입력을 필수화하지 않는다.

읽기 전용 감사에서 발견한 공백: `training.js` 수행 비교에는 순서·선행 운동 조건이 없고 같은 세션의 반복 블록을 합친다. `coach-query.js`는 종목 필터링 뒤 원문을 축약하므로 선행 운동이 빠질 수 있다. 실제 일지의 실행 순서·휴식과 보조 부하 역할은 저장되어 있지 않으며 계획의 휴식을 실제 휴식으로 사용할 수 없다. 합성 재현에서는 벤치 계획 2세트 블록 두 개에 실제 단 2세트를 연결했을 때 양쪽 모두 달성으로 표시했다. 실제 세트 하나는 계획 블록 하나의 근거로만 사용할 수 있어야 한다.
