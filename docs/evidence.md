# 비개발자용 설명

이번 엔진은 일반 성인의 영양 목표를 잡는 출발점이다. 성별, 나이, 키, 체중, 선택한 체성분, 운동 경력, 종목, 그날의 운동과 목표를 반영한다. 생활활동은 간단한 활동 수준 또는 선택적 24시간 구분으로 입력할 수 있고, 걷기·달리기는 지원 범위 안의 속도·경사 입력을 사용할 수 있다. 입력이 자세해졌다고 개인별 정확도가 검증되는 것은 아니다. 모든 사람에게 생리학적으로 완벽한 값을 주는 공식이나 건강 점수라고 주장하지 않는다.

이전 앱에서는 체성분이 없는 100kg 성인의 전체 체중을 제지방량처럼 넣어 하루 3,000kcal를 감량 하한으로 만드는 문제가 재현됐다. 예를 들어 45세, 165cm, 100kg 여성의 Mifflin 추정 안정시대사량은 약 1,645kcal인데, 체성분 미입력 때문에 감량 목표가 오히려 커질 수 있었다. 새 엔진은 모르는 제지방량을 빈 값으로 두고, 측정값이 있어도 에너지 가용성 30이라는 한 숫자를 모든 사람의 안전선으로 강제하지 않는다.

정책·산식·데이터 해석이 바뀌었다. 골격근량을 고정 성별 비율로 역산해 기초대사량을 올리는 가정, 운동 횟수로 고급자를 판정하는 가정, 건강을 하나의 점수로 표현하는 방식은 사용하지 않는다. 기록의 원본 값은 이 모듈이 수정하지 않는다. 체지방률이 있으면 입력 체중과 비율로 제지방량을 계산하되, 측정 방법과 날짜가 불확실하면 목표 보정에는 쓰지 않는다.

임신·수유·질환 또는 치료 식이·섭식 문제, 18세 미만, 저체중, 이 모델의 지원 범위를 벗어난 경우에는 처방처럼 보이는 칼로리와 탄단지 숫자를 만들지 않는다. 식사와 체중 기록 기능과는 별개의 경계다. 월경 주기, 약물, 장애, 초장거리 경기의 요구량을 입력 몇 개로 추측하지 않는다. 추가 판단 필요 없음: 일반 성인용 추정과 개별 평가가 필요한 상태를 구분하는 방향으로 구현했다.

검증은 성별·나이·체격·체성분·목표·종목·운동시간 조합의 열량 일치, 계산 연속성, 운동량 증가 방향, 혼합 운동, 체성분 미입력, 지원 범위 밖 숫자 차단, 데이터 불변성을 확인한다. 테스트 통과는 임상적 검증이나 개인별 정확도를 뜻하지 않는다.

## 기술 검증

`src/nutrition.js`는 DOM과 저장소에 의존하지 않는 UMD 모듈이다. `calculatePlan(profile, day, history)`의 상태는 `ready`, `review`, `incomplete`다. `review`와 `incomplete`는 열량·탄단지 숫자를 `null`로 반환한다. 현재 테스트는 `node --test tests/nutrition.test.cjs`로 실행한다.

기존 앱의 유효한 의도인 탄수·지방 교환은 `adjustAllocation(plan, carbDeltaG)`으로 보존한다. 예를 들어 탄수 25g을 늘리면 지방 약 11.1g을 줄여 열량과 단백질을 그대로 둔다. 교환은 두 영양소의 조건부 범위 교집합에서 제한한다. 사용자가 정한 절대 조정량을 기본 배분에 적용하며 같은 값을 반복 호출해도 누적되지 않는다. 실제 섭취를 따라 목표를 자동으로 움직이거나 새 감점을 만들지 않는다.

### 읽은 기준과 범위 감사

- 읽은 기준: `AGENTS.md`, `.agents/skills/macro-engine-product-review/SKILL.md`, `docs/00_current_truth/00_READ_FIRST.txt`, `02_macro_range_current_truth.txt`, `04_document_status_index.txt`, `05_required_result_log_format.txt`. `npm run preflight:product` 통과.
- 실제 문제: 사용자는 개인별로 납득 가능한 영양 조언을 원하지만 기존 구현은 경력 입력 없이 빈도로 숙련도를 추정하고, 체성분 미입력·과도한 골격근 보정·범용 안전선 가정을 혼합했다.
- 문서 밖 증거: 기존 `getTargetRateActualLbm`, `calcSkeletalAdjustment`, `calcBMR`, `getTargetRateTrainingBand`, `inferExternalMacroPolicyContext`와 실제 브라우저 계산을 확인했다.
- 대안: 기존 단일 파일에 추가 계수 패치, 단순 문구 보강, 순수 계산 모듈 재작성. 사용자의 명시적 리빌딩 허용에 따라 순수 계산 모듈을 선택했다.
- 반증 조건: 목표 탄단지의 열량 합이 목표와 다름, 운동을 더했는데 탄수·열량이 감소함, 측정하지 않은 제지방량을 단정함, 건강상태가 지원 밖인데 처방 숫자를 냄, 연속 입력의 작은 변화가 목표를 크게 바꿈.
- 최소 표면: 새 영양 엔진, 해당 테스트, 근거 원장. 이 범위 안에서 입력 검증·지원 대상·범위·근거·운동 조언까지 완결한다.
- 수용: 실제 체성분, 운동 경력, 운동 종목과 목표를 분리한다. 생리학적 개인차와 추정 오차를 드러낸다.
- 폐기: 보편적 EA 하한, 운동 횟수로 경력 추정, 가짜 골격근→제지방 역산, 건강점수.
- 통합: 외부 영양 권고와 연속적인 제품 보간, 운동의 순 소모량, 목표 열량 내의 탄단지 배분.
- 보류: 질환별 처방, 성장기·임신·수유 계획, 직접 측정 안정시대사량, 개인별 대사 적응 추정, 경기일 전용 보급 엔진.
- 금지선: 기록 무단 변경, 문헌 권고를 개인의 확정값으로 포장, `ready`를 안전 판정으로 표현, 일일 체중 변동을 지방 증감으로 해석.
- 다음 단계: UI와 저장 모듈에서 이 상태·범위·출처를 그대로 소비하고, 실제 사용자 추세와 외부 전문가 검토로 보정 모델을 평가한다.

### 대표 MET 대응

- 근력: 쉬움 3.0, 보통 3.5, 강함 6.0. [Conditioning activities](https://pacompendium.com/conditioning-exercise/).
- 달리기: 6.5 / 8.5 / 11.0. [Running activities](https://pacompendium.com/running/). 입력 강도만으로 실제 속도는 알 수 없으므로 대표값이다.
- 자전거: 4.3 / 7.0 / 9.0. [Bicycling activities](https://pacompendium.com/bicycling/).
- 수영: 5.8 / 8.0 / 9.8. [Water activities](https://pacompendium.com/water-activities/).
- 구기: 4.0 / 6.0 / 8.0. [Sports activities](https://pacompendium.com/sports/)의 여러 활동을 대표하는 제품 매핑이다.
- 복합: 3.5 / 5.0 / 7.5. 서킷 운동 참고값이다. 종목별 시간을 아는 경우 각각 기록하는 편이 낫다.
- 걷기: 2.8 / 3.8 / 4.8. [Walking activities](https://pacompendium.com/walking/)의 대표적인 느림/보통/빠름 값을 참고한다. 일상 산책을 운동선수 단백질·보급 요구로 즉시 바꾸지 않는다. 운동 프로필이 없는 사용자의 첫 세션은 시간에 따라 연속적으로 단백질 계획에 반영한다.

운동 프로필이 없는 사용자의 단백질 보간은 일반 운동시간 120분, 근력시간 90분을 지수 곡선의 척도로 쓴다. 걷기는 일반 운동시간 가중치 0.2다. 이는 생리학 논문이 정한 시간이 아닌 보수적인 제품 보간이다. 아주 짧은 근력 운동 추가가 탄수 목표를 오히려 줄이는 반례를 확인해 곡선을 완화했고, 모든 지원 종목과 강도의 0~180분 증가 구간을 회귀 검증했다.

### 선택적 24시간 활동 모델

[FAO/WHO/UNU의 성인 에너지 요구량 보고서](https://www.fao.org/4/y5686e/y5686e07.htm)는 활동별 시간과 기초대사 대비 활동비(PAR)를 조합하는 방법을 설명한다. PAR은 MET와 기준이 같지 않다. 이 앱은 보고서 예시에서 수면 1.0, 가벼운 휴식 1.4, 앉은 일 1.5, 선 일 2.2, 육체노동 4.1, 가벼운 생활활동 2.1, 활동적인 생활활동 3.2를 골라 단순한 입력 분류에 대응시켰다. 직업명만으로 실제 업무 강도가 확인되는 것은 아니다.

간단 모드는 기존 `Mifflin RMR × 생활활동 배수 + 순운동 소모`를 유지한다. 24시간 모드는 `RMR/24 × 비운동 활동별 PAR·시간의 합 + 운동 총소모`를 사용한다. 수면·업무·생활활동·실제 운동을 중복 없이 입력하고, 남은 시간은 가벼운 휴식으로 채운다. 시간이 누락되거나 합이 24시간을 넘으면 임의 비율 보정 대신 계산에 필요한 입력을 요청한다. 기본 시간표, 요일 시간표, 해당 날짜 시간표 순으로 선택할 수 있으며 날짜 입력이 있으면 시간표 전체를 대체한다.

이는 Mifflin의 RMR 추정, BMR 기준의 FAO PAR, MET 또는 ACSM 운동식을 결합한 **제품의 혼합 모델**이다. FAO 원 모델의 그대로인 구현도, 개인별로 검증된 에너지 소비식도 아니다. 상세 입력을 정확도 보증으로 표시하지 않으며 별도의 식이성 열발생 수치를 추가하지 않는다. 목표 조정용 기본값에서는 운동시간을 가벼운 휴식으로 치환한다. 따라서 상세 모드의 운동으로 인한 증가분과 별도로 표시하는 관례적 순운동 소모는 같지 않을 수 있다.

### 걷기·달리기의 속도와 경사

지원하는 걷기·달리기의 선택 입력에는 ACSM 식을 사용한다. 속도 `S`는 m/min, 경사 `G`는 비율이며, 산소소비 추정값은 걷기 `3.5 + 0.1S + 1.8SG`, 달리기 `3.5 + 0.2S + 0.9SG`(mL/kg/min)다. 이를 체중·운동시간과 5kcal/L 가정으로 열량으로 바꾸며, 순소모는 같은 식의 3.5 항에 해당하는 휴식량을 뺀다. 식의 형태와 적용 한계는 [걷기 검증 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC7896743/), [달리기 식의 적용 맥락을 평가한 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC3743617/)를 참고했다. 속도로 VO2max나 체력을 측정하지 않는다.

제품은 걷기 3~6km/h, 달리기 8.1~20km/h, 트레드밀 경사 0~15%로 입력을 제한한다. 야외는 경사 0만 받는 평지 근사이고 별도 한계를 표시한다. 이 상·하한 자체가 개인별 타당성을 검증한 범위는 아니다. 일정한 속도의 유산소 활동을 위한 참고식이며 인터벌·내리막·손잡이 지지·운반 부하·노면·바람을 반영하지 못한다. 범위를 벗어난 상세 입력을 다른 식으로 조용히 대체하지 않으며, 사용자가 상세 입력을 해제한 경우에만 강도별 대표 MET를 사용한다.

### 측정과 추세의 해석

체성분은 측정 당시 체중(`bodyFatWeightKg`), 측정 방법과 날짜가 함께 있어야 목표에 사용한다. 예전 80kg·체지방 20%의 측정은 제지방 참고량 64kg으로 남으며, 오늘 70kg이 됐다고 과거 비율을 곱해 56kg으로 바꾸지 않는다. 짝지은 체중이 없으면 현재 체중을 대신 끼워 넣지 않고 제지방량은 null이다.

경과 30일부터 180일까지, 현재 체중과 측정 당시 체중 차이 0~10% 구간에서 각각 smoothstep으로 목표 보정의 반영 정도를 줄인다. 180일 또는 체중 10% 차이에 도달하면 체성분 없는 기본 추정으로 연속적으로 돌아간다. 이 기간·비율은 의학적으로 정확성이 보장되는 기준이 아니라 오래되거나 달라진 몸의 값을 무기한 적용하지 않는 제품 정책이다. DXA도 절대 진실로 취급하지 않으며 BIA와 피부두겹 측정은 더 낮은 신뢰도로 표시한다. 표시되는 FFM과 이를 사용한 에너지 가용성은 측정 당시 자료의 참고 계산이며 현재의 재측정값이 아니다.

체중 추세는 최근 42일 안에서 14일 이상에 걸친 최소 4회 측정이 있을 때 7일 이상 떨어진 관측쌍의 기울기 중앙값으로 계산한다. 충돌하는 같은 날짜 측정은 제외한다. 식사 누락, 수분과 글리코겐 변화, 실제 소모의 오차를 분리할 수 없으므로 추세를 열량에 자동 반영하지 않는다. 이 기준도 제품의 데이터 충분성 정책이다.

화면의 최근 2주 요약은 별도의 관찰 요약이다. 두 주에 각각 최소 3회 측정이 있고 대표 날짜 사이가 5일 이상일 때 주간 중앙값의 변화를 보여 준다. 섭취·체중·체지방률·골격근량 그래프의 7/14/28/42일 선택은 측정 기록을 그리는 범위이며, 빈 날짜를 0이나 준수 실패로 채우지 않는다. 섭취와 목표의 평균 비교에는 식사가 있고 완료 당시 계산 가능한 목표가 저장된 날짜만 사용한다. 서로 다른 목표가 섞이면 이를 표시하고, 과거 목표를 현재 프로필로 다시 계산하지 않는다.

### 식사 기록과 관찰 기반 배분

끼니 종류·메모·식사 템플릿은 기록의 편의를 위한 정보다. 어제 식사 복사는 항목을 고르고 같은 내용이 이미 있는지 확인한 뒤 적용하며, 중복 의심만으로 기존 기록을 삭제하지 않는다. 음주 계산은 사용자가 확인한 용량·도수·수량에 `용량(mL) × 도수/100 × 수량 × 0.789`를 적용해 알코올 g을 채우는 편의 계산이다. 알코올은 7kcal/g으로 별도 합산하고 음료의 탄수화물은 별도 입력한다. 혈중알코올이나 개인별 위해도를 계산하지 않는다.

최근 식사 비율 제안은 선택일 이전 28일 중 같은 목표로 완료한 유효 기록이 최소 4일 있을 때만 제공한다. 알코올·기타 열량이 있는 날은 제외하고 탄수·지방 열량 비율의 중앙값을 현재 목표의 교환 가능 범위에 적용한다. **현재 총열량과 단백질은 그대로 유지**하며 사용자가 미리보고 적용해야 한다. 실제로 먹은 양을 최적 식단으로 인정하거나 목표를 섭취량에 자동 추종시키는 기능이 아니다. 부족한 기록은 제안을 보류하고 같은 조정을 반복 적용해도 누적하지 않는다.

날짜별 백업 병합은 확인한 신규 날짜와 선택한 미완료 충돌 날짜만 적용한다. 완료한 날짜는 보호하며 프로필·훈련 계획·대화 기억을 날짜 병합으로 대체하지 않는다. 전체 복원은 별도의 검증·미리보기 흐름이다. 데이터 병합과 영양 목표 계산은 서로 독립적이다.

## 코칭과 근력 기록의 적용 범위

앱코치는 식사·운동·목표·완료 여부·최근 기록과 선택적 회복 자기보고를 함께 해석한다. 실제 세트 일지, 부위별 기록, 수행 변화와 다음 훈련 초안을 연결했지만, 개인을 직접 평가하는 PT나 의료진의 판단을 대체하지 않는다. 근력 분석의 논문·공식 권고와 제품 선택은 [근력 근거 문서](training-evidence.md)에 따로 정리했다.

- 세트의 중량·반복·RIR·원문 표기, 운동명과 확인한 장비·중량 규약을 보존한다. 직접·간접 세트는 별도 기록 집계이며 실제 근활성·유효 자극량·성장률이 아니다. 준비 세트는 세트에 명시된 W로만 제외하고 다른 문자 표시는 의미를 추측하지 않는다.
- 같은 이름만으로 서로 다른 머신을 비교하지 않는다. 중량·반복의 전후 값은 미확인 RIR이 있어도 관찰값으로 보여 주지만, 조건 내 수행 증가 판정에는 동일 장비·확인된 중량 규약·기록 RIR·일반 세트 수 등 비교 조건이 필요하다. 조건이 같아도 자세·동작 범위·휴식이 같다는 보장이나 근성장 측정은 아니다.
- 회복은 수면·허기·컨디션·수행 자기보고와 실제 기록을 구분해 읽는다. 비교 가능한 수행이 반복 감소하고 최근 회복 신호도 있을 때 디로드를 검토하도록 안내한다. 단일 저하나 기록이 없는 날짜를 과훈련·휴식으로 확정하지 않으며, 섭취량이나 훈련량을 자동으로 줄이지 않는다.
- 프로그램은 경력·목표·가능한 요일 수와 시간·장비·우선 부위에 맞춘 시작 템플릿이다. 사용자는 이를 저장·편집하고 실제 날짜에 배치한 뒤 같은 날짜의 실제 기록과 연결할 수 있다. 세트·반복·RIR·휴식 목표는 기록값과 별개이며 숫자상 계획 이행이 자극·기술·회복의 적절함을 뜻하지 않는다. 조정과 디로드는 이유·재검토 날짜를 포함한 명시적 선택이다. 임상·통증 등 지원 밖 상황은 개별 확인이 먼저다.
- 운동일지의 Cal·총 kg는 영양 목표에 자동 가산하지 않는다. 사용자가 확인한 실제 시간·종목·강도만 별도로 연결하며 선택한 활동 모드의 소모 추정을 사용한다. 일지 수정이나 AI 응답은 완료 당시 영양 목표를 재계산하지 않는다.
- 앱 계산·기록 요약과 생성 AI 상담은 역할과 출처를 구분한다. 규칙 응답을 자유로운 상담의 대체재로 표시하지 않는다. 생성 AI가 유창하게 말하거나 연구를 언급해도 답변 자체가 연구 근거·검증된 개인 처방·진단이 되는 것은 아니다. 감지한 통증·긴급 증상은 AI 요청보다 먼저 로컬 중단·의료 도움 안내로 연결하지만, 이 문구 탐지는 포괄적 임상 선별검사가 아니다. 이미지 보관은 숫자 기록이 아니며 판독은 확인 전 초안이다. 읽지 못한 숫자는 null로 남긴다.

개인 기억은 사용자가 확인한 제약·우선순위·합의이며 AI가 만든 문장을 자동으로 사실로 저장하지 않는다. 검토할 약속은 주제·내용·날짜와 열린 상태/완료 상태를 따로 저장한다. AI에는 최근 기록과 질문에 해당하는 일부 과거 맥락을 제공하므로 모든 장기 기억을 빠짐없이 회수하는 기능은 아니다. 기록 요약과 Codex 상담은 같은 입력·계산 함수를 사용하고 상담마다 사진을 다시 판독하지 않는다. AI에는 집계와 원문 일부를 함께 전달하지만 입력·분류 오류를 공유하므로 독립적인 정확성 검증이 아니다. 기록 요약도 AI 상담도 진단은 아니다.

Codex 답변의 구조화된 수치 근거는 서버가 전달한 사실 ID·값·단위·출처와 대조하고, 표시 문장에 근거 없는 수치가 발견되면 응답을 거부한다. 입력된 관찰값과 모델 추정값도 구분한다. 이는 숫자 출처를 좁히는 방어 장치이지 자유 문장의 인과관계·누락·운동 기술·임상 안전성을 검증하는 장치가 아니다. AI가 제안한 후속 약속도 확인 전에는 계획이나 기록을 바꾸지 않는다.

이 연결은 일반 성인의 기록 기반 코칭 범위를 넓힌 것이지 모든 성별·연령·임상군·종목에 보편적으로 타당한 개인 코치를 검증한 것이 아니다. 운동 수행, 사진, 체중 변화만으로 근육 성장량·호르몬 상태·질환·손상 원인을 추론하지 않는다.
